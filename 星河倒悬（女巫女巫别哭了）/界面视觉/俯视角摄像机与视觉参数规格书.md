# 俯视角摄像机与视觉参数——完整规格书

> **定位：** 俯视角斜45°摄像机的精确参数。解决"视野够大+人物细节可见"的矛盾。
> **核心结论：** 基准可视范围 **28m×20m**·角色约 **92px**（1080p下）·桃木剑~54px清晰可见·葫芦~16px可辨识。
> **取代：** 本文档取代 `战斗摄像机与镜头设计.md`（该文档为3D肩后视角设计·已不适用·保留归档）
> **关联：** [[世界地图与区域解锁设计]] §十 | [[战斗系统GDD]]

## 一、核心参数

### 1.1 基准摄像机

| 参数 | 值 | 说明 |
|------|-----|------|
| 视角类型 | 斜45°俯视 | 经典ARPG视角·非完全垂直·保留立体感 |
| 摄像机高度 | 15m（虚拟） | 对应28m×20m的可视范围 |
| 水平可视范围 | 28m | 屏幕宽度对应的游戏世界宽度 |
| 垂直可视范围 | 20m | 屏幕高度对应的游戏世界高度 |
| 屏幕分辨率基准 | 1920×1080 | 所有像素计算以此为准 |
| 像素密度 | 54 px/m | 1080px ÷ 20m |
| FOV | 约60° | 斜45°俯视下·通过摄像机高度控制范围 |

### 1.2 角色可见性验证（1080p·基准距离）

| 可见物 | 实际尺寸 | 屏幕像素 | 可见程度 |
|------|:--:|:--:|------|
| 辰生（全身·身高1.7m） | 1.7m | 92px | ✅ 全身细节可见·衣袍纹理·星纹位置 |
| 桃木剑（剑身1.0m） | 1.0m | 54px | ✅ 剑身形状·颜色·火焰/雷电附着效果 |
| 铜钱剑（剑身0.9m） | 0.9m | 49px | ✅ 铜钱串的轮廓·与桃木剑明显不同 |
| 七星剑（剑身1.1m） | 1.1m | 59px | ✅ 剑身七颗宝石闪光·敕令蓄力光效 |
| 银针（0.4m） | 0.4m | 22px | ✅ 针的细长形状·光点可辨识 |
| 葫芦（0.3m） | 0.3m | 16px | ✅ 腰间的葫芦形状·颜色可辨识 |
| 八卦盘（手持·直径0.25m） | 0.25m | 14px | ✅ 演卦时的圆形光环·八卦纹路隐约可见 |
| 星纹（手腕·0.05m） | 0.05m | 3px | ⚠️ 太小·需要发光效果来补偿 |
| 脸（0.2m） | 0.2m | 11px | ⚠️ 表情不可辨识·需要对话时弹出立绘 |

### 1.3 与其他分辨率的关系

| 分辨率 | 像素密度 | 角色像素 | 说明 |
|------|:--:|:--:|------|
| 1920×1080（基准） | 54 px/m | 92px | 标准 |
| 2560×1440（2K） | 72 px/m | 122px | 细节更丰富·推荐 |
| 3840×2160（4K） | 108 px/m | 184px | 奢侈级别·所有细节完美 |
| 1280×720（最低） | 36 px/m | 61px | 角色仍可辨识·但葫芦模糊 |

> **最低要求：** 1280×720。低于此分辨率·葫芦和银针将不可辨识。

## 二、场景动态缩放

摄像机不是固定的——不同场景使用不同的可视范围，平滑过渡。

### 2.1 缩放参数表

| 场景 | 可视范围 | 缩放系数 | 角色像素 | 过渡时间 | 说明 |
|------|:--:|:--:|:--:|:--:|------|
| **野外探索（基准）** | 28m×20m | 1.0× | 92px | — | 默认·看路看远处 |
| **野外·开阔地带** | 30m×22m | 0.93× | 83px | 1.0s | 视野最大化·骑马/奔跑 |
| **战斗·普通遇敌** | 26m×19m | 1.08× | 97px | 0.8s | 战斗触发时自动缩进 |
| **战斗·BOSS** | 24m×17m | 1.17× | 108px | 1.0s | 看清BOSS弹窗·地面范围 |
| **战斗·精英** | 25m×18m | 1.12× | 102px | 0.8s | 精英战·中等距离 |
| **道宫内部** | 22m×16m | 1.27× | 115px | 0.5s | 封闭空间·走廊窄 |
| **道宫BOSS房** | 24m×17m | 1.17× | 108px | 1.0s | BOSS封印之间 |
| **村落·室外** | 20m×14m | 1.40× | 131px | 0.8s | 看NPC·建筑·对话 |
| **村落·室内** | 14m×10m | 2.00× | 184px | 0.5s | 最细节·看同伴表情 |
| **演卦选卦** | 24m×17m | 1.17× | 108px | 0.3s | 卦盘UI在屏幕中央·需要空间 |
| **梅花易数观象** | 28m×20m | 1.00× | 92px | 0.5s | 观象范围=屏幕范围 |
| **过场演出** | 可变 | 可变 | — | 根据演出需要 | BOSS阶段转换·同伴觉醒 |

### 2.2 缩放触发规则

```
进入战斗（3个以上敌人·或精英/BOSS出现）→ 自动缩进到战斗距离
战斗结束（所有敌人死亡）→ 2.0s后自动恢复到探索距离

进入村庄 → 自动缩进到村落距离
离开村庄 → 自动恢复

进入道宫 → 自动缩进到道宫距离
进入BOSS房 → 进一步缩进到BOSS距离

玩家手动缩放（可选）→ 鼠标滚轮 ±10%（范围限制·不能超过场景上/下限）
```

### 2.3 过渡动画

```
摄像机缩放过渡曲线：ease-in-out
  - 缩进（战斗触发）：0.8s·先慢后快（紧张感）
  - 恢复（战斗结束）：2.0s·先快后慢（放松感）
  - 场景切换：0.5s·线性（快速定位）
```

## 三、角色在俯视角下的视觉设计

### 3.1 角色轮廓——不同法器的"剪影辨识"

在92px的角色高度下，不同法器应形成明显不同的轮廓：

| 法器 | 角色剪影特征 | 辨识点 |
|------|------------|------|
| **银针** | 右手持针·手在前方·纤细 | 无长兵器轮廓·手前有光点 |
| **桃木剑** | 右手持剑·剑斜跨身体·暗金色剑身 | 暗金色长条·与角色身体形成交叉角度 |
| **铜钱剑** | 右手持剑·剑身柔软弯曲·红色丝线 | 弯曲的轮廓·铜钱黄色·丝线红色 |
| **七星剑** | 双手持剑（重）·剑身竖直·七点亮光 | 最长的武器轮廓·剑身粗·七点蓝白星光 |
| **演卦中** | 左手掐诀·右手持剑·身周八卦盘光环 | 圆形光环+角色+剑的三层结构 |

### 3.2 颜色编码——远距离辨识

在极限视野（30m×22m·角色83px）下，颜色比形状更重要：

| 元素 | 颜色信号 | 说明 |
|------|---------|------|
| 辰生·默认 | 青白道袍+暗金星纹 | 青白是地图上少见的颜色·容易定位 |
| 离卦上身 | 角色变橙红+火焰尾迹 | 一眼看出"在火里" |
| 震卦上身 | 角色变蓝白+电弧闪烁 | "带电了" |
| 坎卦上身 | 角色变深蓝+水滴光效 | "在水里" |
| 艮卦上身 | 角色变土黄+身体变"重" | "变硬了" |
| 受伤(HP<30%) | 角色闪烁红光·频率递增 | 紧急信号 |
| 濒死 | 角色+屏幕边缘红框 | 最强警告 |

## 五、粒子/特效在俯视角下的表现

### 5.1 特效可见性要求

俯视角下·特效不能太小（看不清）·也不能太大（遮住敌人）：

| 特效 | 最小可见尺寸 | 屏幕尺寸 | 说明 |
|------|:--:|:--:|------|
| 卦术命中火花 | 0.5m | 27px | 明显的命中反馈 |
| 灼烧火焰 | 0.8m | 43px | 敌人身上可见的火焰 |
| 地面残留（火/冰/雷） | 1.5m | 81px | 清晰的地面区域标记·不遮挡角色 |
| 卦术AOE范围 | 3-8m | 162-432px | 弹窗范围指示·半透明 |
| 太乙神数全屏 | 全屏 | 1920×1080px | 天地变色 |
| 步罡踏斗脚印 | 1.0m/脚印 | 54px | 北斗七星清晰可见 |
| 白色小火焰(伪卦) | 0.3m | 16px | 火花可见·需要适当加大 |
| 金色真火 | 0.5m | 27px | 明显比白焰大·颜色区分 |

### 5.2 特效层次

```
渲染顺序（从底到顶）：
  1. 地面特效（火区域·冰面·毒沼）  ← 最底层·半透明
  2. 环境粒子（火山灰·飘雪·落叶）    ← 氛围层
  3. 敌人AOE弹窗范围                 ← 红色半透明
  4. 角色和敌人                      ← 实体层
  5. 卦术飞行弹道（火球·冰锥·雷击）   ← 快速移动·高亮
  6. 命中特效（火花·hit-stop闪光）    ← 短暂·强烈
  7. UI层                            ← 最顶层·不参与游戏世界渲染
```

## 七、角色美术方向建议

基于92px的基准角色高度，美术设计需要遵循的原则：

| 原则 | 说明 |
|------|------|
| **法器优先** | 武器是角色身上最大的物体（54-59px）·必须设计得从轮廓就能分辨四法器 |
| **颜色信号强化** | 8种卦象的颜色变化必须显著（不只是"微弱的火光"·是"整个人变橙红"） |
| **粗线条** | 角色模型的轮廓线条在92px下不能太细·参考哈迪斯的美术风格 |
| **关键发光** | 星纹·剑尖·法器切换的光效·用发光补偿小尺寸的不足 |
| **夸张比例** | 葫芦和剑可以比现实比例大10-20%·在俯视角下更可见 |
| **简化面部** | 92px下不需要精细面部·头发和头饰是辨识角色的关键 |

## 八、技术实现要点

### 8.1 摄像机设置（Unity伪代码）

```csharp
// 俯视角摄像机控制器
public class TopDownCamera : MonoBehaviour
{
    [Header("基准参数")]
    public float baseHeight = 15f;           // 摄像机高度
    public float baseAngle = 45f;            // 俯角
    public Vector2 baseViewSize = new(28f, 20f); // 基准可视范围
    
    [Header("场景缩放")]
    public float exploreZoom = 1.0f;         // 野外探索
    public float combatZoom = 1.08f;         // 普通战斗
    public float bossZoom = 1.17f;           // BOSS战
    public float villageZoom = 1.40f;        // 村落
    public float indoorZoom = 2.00f;         // 室内
    
    [Header("过渡")]
    public float zoomSpeed = 2.0f;           // 缩放过渡速度
    public AnimationCurve zoomCurve;         // 缩放曲线
    
    private float targetZoom = 1.0f;
    private float currentZoom = 1.0f;
    
    void Update()
    {
        // 平滑过渡到目标缩放
        currentZoom = Mathf.Lerp(currentZoom, targetZoom, 
            zoomSpeed * Time.deltaTime);
        
        // 调整摄像机高度实现缩放
        float height = baseHeight / currentZoom;
        transform.position = target.position + Vector3.up * height 
            + Vector3.back * height * Mathf.Tan(baseAngle * Mathf.Deg2Rad);
        transform.LookAt(target.position);
    }
    
    public void SetSceneZoom(SceneType scene)
    {
        targetZoom = scene switch
        {
            SceneType.Explore => exploreZoom,
            SceneType.Combat => combatZoom,
            SceneType.Boss => bossZoom,
            SceneType.Village => villageZoom,
            SceneType.Indoor => indoorZoom,
            _ => exploreZoom
        };
    }
}
```

### 8.2 性能预算

| 项目 | 预算 |
|------|------|
| 摄像机更新 | 每帧·Lerp计算·<0.01ms |
| 同屏敌人上限 | 基准距离12个·极限距离15个 |
| 同屏特效粒子 | 基准距离500个·极限300个 |
| 角色模型面数 | 2000-3000三角面（92px不需要高精度·但法器和衣袍轮廓要清晰） |
| 场景面数 | 俯视角看不到远处·LOD简化·近处高精度远处低精度 |
