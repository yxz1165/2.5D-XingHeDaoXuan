# 六爻纳币——钱币消耗与经济进阶系统（完整设计）

> **定位：** 三钱摇卦系统的经济进阶层。将虚拟的「5文摇卦」升级为真实的「18枚钱币分爻配币→消耗→影响卦象概率」的完整经济循环。以真实历史货币体系（文·两白银·两黄金）为基础，打造有重量的经济决策。
> **设计日期：** 2026-08-08
> **字数：** ~35,000字

---

## 〇、设计总纲

### 0.1 核心命题

现有三钱摇卦系统的问题：

- 成本 5 文铜钱 + 20 卦气——太便宜，没有决策重量
- 钱币是视觉效果——铜钱飞出去、落地、判定，但玩家感觉不到「花掉了什么」
- 缺乏经济梯度——从前期到终局，摇卦的成本始终不变
- 与锻造系统无竞争关系——锻造花大钱、摇卦花零钱，玩家不需要在两者之间取舍

本设计的核心命题：

> **让每一枚掷出去的铜钱都有真实的重量。玩家在六爻的每一爻上都要决定——这一爻，用几分钱的诚意？**

### 0.2 设计目标

```
1. 真实货币体系
   └→ 文·两白银·两黄金·1两银=1000文·1两金=10两银=10000文
   
2. 18枚钱币分爻消耗
   └→ 六爻各3枚·总计18枚·每爻独立选择钱币品质·掷出后消失
   
3. 钱币品质影响概率
   └→ 高品质钱币微调阳面倾向·间接影响变爻/老阳概率·增强启示Buff·降低代价·提升稀有卦效果
   
4. 五阶钱币+特殊五帝钱
   └→ 铜钱→当十钱→银钱→金钱→厌胜金宝→五帝钱(不消耗·冷却制)
   
5. 经济自然梯度
   └→ 玩家钱包自然限制其钱币选择·无需系统硬性规定
   
6. 连摇翻倍机制
   └→ "再摇一次"的成本每次翻倍·追求完美启示的沉没成本钩子
   
7. 定制卦象（终局内容）
   └→ 厌胜金宝+五帝钱允许手动指定爻位·终极经济出口
```

### 0.3 与现有系统的关系

```
三钱摇卦系统（基础版·序章解锁）
├─ 5文+20卦气·标准概率
├─ 适合日常探索·刷材料·新手阶段
├─ 钱币是虚拟的（视觉效果·不消耗实物）
└─ 永久可用·不因解锁进阶版而失效

六爻纳币系统（进阶版·大梁宫后解锁）
├─ 18枚真实钱币·按爻配币·掷出消耗
├─ 适合BOSS战前·追求特定启示·高风险高回报
├─ 与锻造系统竞争铜钱/白银/黄金资源
└─ 与五帝钱收集系统交叉·五帝钱可跨系统使用

两者并存·玩家自由选择。基础版是拐杖·进阶版是大师工具。
```

### 1.2 游戏内钱包统一表示

> **⚠️ 兼容声明：** 本文档不重新定义 `Wallet` 类。现有 `Wallet`（见 `经济系统设计.md` §8.1）保持唯一权威：`int copperCoin` + `int starCrystal` + `CurrencyType` 枚举。以下 `MoneyFormatter` 为纯工具类，从现有 `Wallet.copperCoin` 读取数值并格式化显示，不改变任何存储结构。

```csharp
/// <summary>
/// 货币格式化工具——从现有Wallet.copperCoin读取·输出金/银/铜显示字符串。
/// 纯静态工具·不持有状态·与现有Wallet完全兼容。
/// </summary>
public static class MoneyFormatter {
    // 换算常量
    public const int WEN_PER_SILVER_TAEL = 1000;   // 1两银 = 1000文
    public const int SILVER_PER_GOLD_TAEL = 10;     // 1两金 = 10两银
    public const int WEN_PER_GOLD_TAEL = 10000;     // 1两金 = 10000文
    
    /// <summary>
    /// 将铜钱数（文）格式化为金/银/铜显示字符串
    /// </summary>
    public static string Format(int totalWen) {
        int gold = totalWen / 10000;
        int silver = (totalWen / 1000) % 10;
        int copper = totalWen % 1000;
        
        if (gold > 0) {
            if (gold >= 100)
                return $"{gold}两金";              // 大额省略银和铜
            if (silver > 0)
                return $"{gold}两金{silver}两银{copper}文";
            return $"{gold}两金{copper}文";
        }
        if (silver > 0)
            return $"{silver}两银{copper}文";
        return $"{copper}文";
    }
    
    /// <summary>折合白银两数</summary>
    public static float ToSilverTaels(int totalWen) => totalWen / 1000f;
    
    /// <summary>折合黄金两数</summary>
    public static float ToGoldTaels(int totalWen) => totalWen / 10000f;
}

// === 显示规则 ===
// 小于1两银（<1000文）→ "847文"
// 1两到10两之间 → "12两350文"
// 超过10两（≥1两金）→ "3两金6两银200文"
// 超过100两金 → "104两金"（省略银和文·取整）
```

### 1.3 货币重量与携带的叙事意义

在真实历史上，铜钱非常沉重。一贯铜钱（1,000 文）重约 6-8 斤（约 3-4 公斤）。这意味着：

```
携带100两白银 = 100,000文 = 100贯铜钱
  → 100贯铜钱重约600-800斤（约300-400公斤）
  → 一个人根本背不动
  → 大量铜钱必须兑换成白银或黄金才能携带
  
游戏中的叙事逻辑：
  辰生随身携带的钱袋里主要是白银碎块和少量铜钱
  大额交易用白银·小额买卖用铜钱
  "我口袋里叮叮当当的铜钱约有二百来文·腰带里还缝着三两碎银"
```

这一重量逻辑被融入游戏机制——**六爻纳币时，铜钱是实物，掷出去就没了；银钱和金钱更是贵重，掷出去有明显的「心疼感」。**

### 2.2 每阶钱币的概率效果

钱币品质影响四个维度：

```
维度一：阳面倾向——在基础硬币正面概率（p=0.500）之上微调·间接影响变爻概率
维度二：启示Buff倍率——启示正面效果的强度乘数
维度三：代价减免——启示负面代价的减弱比例
维度四：稀有卦效果加成——泰卦(䷊)·既济(䷾)·六爻全变等稀有事件出现时·启示效果的额外乘数
```

| 阶 | 名称 | 阳面倾向/枚 | Buff倍率 | 代价减免 | 稀有卦倍率 | 特色效果 |
|:--:|------|:--:|:--:|:--:|:--:|------|
| 1 | 铜钱 | p=0.500（基准） | ×1.00 | 0% | ×1.0 | 无 |
| 2 | 当十钱 | p=0.510（+0.010） | ×1.02 | 3% | ×1.0 | 累计9枚当十以上→变爻出吉位概率+5% |
| 3 | 银钱 | p=0.515（+0.015） | ×1.04 | 5% | ×1.2 | 累计6枚银钱以上→启示代价再减10% |
| 4 | 金钱 | p=0.525（+0.025） | ×1.06 | 8% | ×1.5 | 累计3枚金钱以上→凶卦(否/剥/困等)自动重roll一次 |
| 5 | 厌胜金宝 | p=0.540（+0.040） | ×1.10 | 12% | ×2.0 | 累计3枚厌胜以上→解锁分爻配币界面中的"爻位阴阳锁定"开关（仅UI功能解锁·实际定制卦象仍需满足§9条件） |

**重要：** 表头的"阳面倾向"是指每枚钱币掷出正面（阳）的单个概率微调，**不直接等于变爻概率加成**。例如3枚金钱（p=0.525×3）的变爻概率从25%升至25.19%（仅+0.19个百分点·远小于3%）。钱币不买结果——只略微倾斜天平。详见第四章概率推导。

## 三、18枚分爻配币机制

### 3.1 为什么是 18 枚而不是 3 枚

传统三钱法用 3 枚铜钱掷 6 次——核心奥义在于**每次掷都独立于前一次**。如果把 3 枚铜钱打包成「一次性的」、掷一次就消耗，那就只剩下 1 爻的判断——不够六爻成卦。

而如果使用 18 枚钱币（6 爻 × 3 枚/爻）：

```
每枚钱币 = 一个独立的概率单元
每爻 3 枚 = 你为这个位置的爻投入的"代价"决定它的"质量"
6 爻合计 18 枚 = 一次完整的卦象 + 一次完整的经济决策

玩家在每一爻都要决定：
  "初爻是根基·普攻加成·用普通铜钱就够了"
  "五爻是君位·卦气消耗-25%·值得砸3枚银钱甚至金钱"
  "上爻是保命·濒死触发空亡·用当十保底·不能只放铜钱"
```

### 3.2 六爻位置与战术价值

在传统六爻纳甲体系中，每一爻有固定的位置含义。游戏中的变爻效果与位置绑定：

| 爻位 | 编号 | 传统含义 | 身体部位 | 社会阶层 | 变爻游戏效果 | 战术评级 | 推荐钱币 |
|:--:|:--:|------|:--:|------|------|:--:|:--:|
| **初爻** | 0 | 潜龙勿用·根基 | 足 | 庶民 | 普攻第一段伤害+30% | ⭐⭐ | 铜钱/当十 |
| **二爻** | 1 | 见龙在田·行动 | 胫 | 士人 | 闪避后1秒内卦术瞬发 | ⭐⭐⭐⭐ | 当十/银钱 |
| **三爻** | 2 | 终日乾乾·进取 | 股 | 大夫 | 第三段攻击附带额外元素伤害(ATK×0.5) | ⭐⭐ | 铜钱/当十 |
| **四爻** | 3 | 或跃在渊·抉择 | 胸 | 公卿 | 同伴被动增益翻倍·持续30秒 | ⭐⭐⭐ | 当十/银钱 |
| **五爻** | 4 | 飞龙在天·治世 | 面 | 天子 | 卦气消耗-25%·整场战斗 | ⭐⭐⭐⭐⭐ | 银钱/金钱/厌胜 |
| **上爻** | 5 | 亢龙有悔·天意 | 首 | 天 | 濒死(HP<15%)自动触发空亡·冷却300秒 | ⭐⭐⭐⭐ | 金钱/厌胜 |

**战术意义：**

- **五爻（君位）= 卦气消耗 -25%** 是全局最强变爻效应——影响的是你整场战斗中释放所有卦术的成本。这是所有追求极限输出的玩家必定投资的位置。玩家会为这 3 枚钱币花掉最多的资源。

- **上爻（天命）= 濒死免死** 是容错率最高的效应。对技术不自信的玩家会重点投资这个位置。对速通/无伤挑战玩家则完全不需要投资——0 文。

- **二爻（行动）= 闪避后瞬发卦术** 是高手的最爱。闪避取消→瞬发卦术→无缝衔接。这个效应能质变战斗手感。高手会在这里砸银钱甚至金钱。

- **初爻和三爻 = 普攻加成** 是新手友好位。效果泛用但不关键。除了「全金流」玩家外，大多数人在这里只放铜钱或当十钱。

**这就形成了一种自然的分层：不同玩家的钱币分布完全不同。**

### 3.3 典型的六种配币策略

#### 策略A：赤贫流（总成本 18 文）

```
初爻[普通×3=3文] 二爻[普通×3=3文] 三爻[普通×3=3文]
四爻[普通×3=3文] 五爻[普通×3=3文] 上爻[普通×3=3文]
总计：18文铜钱·0.018两银 · 无任何加成
适用：日常探索·刷材料·"无所谓·随便摇"
```

#### 策略B：保命流（总成本 315 文）

```
初爻[铜钱×3=3文] 二爻[铜钱×3=3文] 三爻[铜钱×3=3文]
四爻[铜钱×3=3文] 五爻[铜钱×3=3文] 上爻[银钱×3=300文]
总计：15文铜钱+300文银钱=315文·约0.315两银
```

## 四、概率体系的完整数学推导

### 4.1 基础概率——三钱法标准模型

在无任何钱币品质修正的情况下，单次掷三钱（3 枚普通铜钱）的概率分布：

```
三枚铜钱·每枚正面(阳)概率=0.5·反面(阴)概率=0.5

一爻的结果：
  三正（老阳·⚊变爻○）= C(3,3)×(0.5)³ = 1 × 0.125 = 12.5%
  二正一反（少阳·⚊）= C(3,2)×(0.5)³ = 3 × 0.125 = 37.5%
  一正二反（少阴·⚋）= C(3,1)×(0.5)³ = 3 × 0.125 = 37.5%
  三反（老阴·⚋变爻×）= C(3,0)×(0.5)³ = 1 × 0.125 = 12.5%

验证：0.125+0.375+0.375+0.125=1.000 ✓

单个爻为变爻（老阳或老阴）的概率 = 12.5%+12.5% = 25%
单个爻为不变爻（少阳或少阴）的概率 = 37.5%+37.5% = 75%
```

### 4.2 钱币品质修正——单枚钱币的独立概率调整

当爻槽中的 3 枚钱币品质不同时，每枚钱币独立判定，然后汇总：

```
一枚钱币独立掷出正(阳)面的概率 = 0.5 + 该钱币的品质修正值

品质修正值表：
  铜钱：+0.000（p正面=0.5000）
  当十钱：+0.010（p正面=0.5100）  ← 微调·几乎感觉不到
  银钱：+0.015（p正面=0.5150）     ← 极微调
  金钱：+0.025（p正面=0.5250）     ← 稍可感知
  厌胜金宝：+0.040（p正面=0.5400） ← 明显倾向

这些修正值非常微小——设计意图是"钱币影响占卜但不控制占卜"。
占卜的魅力在于不确定性。如果金钱保证阳面，就失去了占卜的意义。
```

**关键设计哲学：钱币修正不是「买结果」，而是「略微倾斜天平」。** 你花了 3,000 文在五爻上，它确实更大概率出你想要的结果——但不能保证。这就是占卜的本质：你尽人事，听天命。

**每爻的计算公式：**

```
给定一爻中的3枚钱币·其正面概率分别为p₁, p₂, p₃

该爻结果为"老阳"的概率 = p₁×p₂×p₃
该爻结果为"老阴"的概率 = (1-p₁)×(1-p₂)×(1-p₃)
该爻结果为"变爻"的概率 = p₁×p₂×p₃ + (1-p₁)×(1-p₂)×(1-p₃)
该爻结果为"少阳"的概率 = 该爻阳面但不全阳 = (至少一阳且非全阳的概率)
```

### 4.3 六爻全卦的概率——18枚钱币的组合效果

给定每爻的变爻概率（p₁到p₆，由各爻配币决定），完整卦象的概率分布：

```
六爻中恰好有k个变爻的概率 =
  所有"选k个爻为变爻·其余6-k个不变"的组合概率之和（非二项分布·因各爻p不同）

计算公式：
  P(k个变爻) = Σ(对每种"k个变爻·6-k个不变"的组合) Π(变爻的p_i) × Π(不变的(1-p_j))

特殊情况：
  六爻全不变：P(0变爻) = Π(i=1→6) (1-p_i)
  六爻全变：P(6变爻) = Π(i=1→6) p_i

对于"全铜钱"（每爻p=0.25）：
  P(0变) = 0.75⁶ = 0.17798 ≈ 17.8%
  P(1变) = 6×0.25×0.75⁵ = 0.35596 ≈ 35.6%
  P(2变) = 15×0.25²×0.75⁴ = 0.29663 ≈ 29.7%
  P(3变) = 20×0.25³×0.75³ = 0.13184 ≈ 13.2%
  P(4变) = 15×0.25⁴×0.75² = 0.03296 ≈ 3.3%
  P(5变) = 6×0.25⁵×0.75¹ = 0.00439 ≈ 0.44%
  P(6变) = 0.25⁶ = 0.00024 ≈ 0.024%（约每4,096次出现1次）
  
  验证：0.178+0.356+0.297+0.132+0.033+0.004+0.0002=1.000 ≈ 0.9992 ✓

对于"全厌胜"（每爻p≈0.2548）：
  P(0变) = 0.7452⁶ ≈ 0.1714 ≈ 17.1%
  P(6变) = 0.2548⁶ ≈ 0.00027 ≈ 0.027%（约每3,700次出现1次）
  
  全变概率从0.024%→0.027%·略微提升·仍然极稀有
```

### 4.4 泰卦(䷊)摇出概率——受钱币影响

泰卦（地天泰·䷊）的六爻构成为：初阳·二阳·三阳·四阴·五阴·上阴。没有变爻时，纯䷊。

```
P(摇出纯泰卦·不变爻) = 
  P(初爻为阳且不变)×P(二阳且不变)×P(三阳且不变)×
  P(四阴且不变)×P(五阴且不变)×P(上阴且不变)

= (阳且不变概率)³ × (阴且不变概率)³

每爻：
  阳且不变 = 少阳概率（非全阳的阳面结果）
  阴且不变 = 少阴概率（非全阴的阴面结果）

对于全铜钱（每枚p=0.5）：
  阳且不变 ≈ 37.5%（少阳）
  阴且不变 ≈ 37.5%（少阴）
  P(泰卦·无变爻) = 0.375³ × 0.375³ = 0.375⁶ = 0.00278 ≈ 0.278%

对于全厌胜（每枚p=0.54）：
  阳且不变（少阳）= 40.24%
  阴且不变（少阴）= 34.28%
  P(泰卦·无变爻) = 0.4024³ × 0.3428³ ≈ 0.0652 × 0.0403 ≈ 0.00263 ≈ 0.263%

实际上泰卦概率变化极小。真正的提升来自稀有卦倍率（厌胜×2.0）——
不是摇出泰卦的概率翻倍，而是摇出泰卦后·启示效果翻倍。
```

### 4.5 吉位变爻修正——最重要的概率效应

前面说的是「变爻概率」的微调。但真正对玩家有意义的是：**变爻出在哪个位置。**

基础概率下，每个爻位的变爻概率独立且相等（25%）。但某些爻位的变爻对玩家更有价值（五爻·君位 > 初爻·根基）。钱币修正让玩家可以「投资」关键爻位：

```
对比：全铜钱 vs 五爻3金钱+其他全铜钱

全铜钱：
  五爻变爻概率 = 25%
  
五爻3金钱+其他全铜钱：
  五爻变爻概率 = 25.19%（仅增加0.19个百分点·来自p正面修正）
  + 金钱累计效应：3枚金钱→凶卦自动重roll一次
  + Buff倍率：×1.06（3枚金钱每枚×1.06·累计?）

等等——我之前定义的是每枚钱币独立贡献Buff倍率。
如果五爻用了3枚金钱，Buff倍率的计算方式应该是：
  金钱对Buff倍率的贡献仅作用于该枚钱币所在的爻。
  如果整个卦的启示Buff来自全卦的综合判定，那么...

让我重新明确Buff倍率的计算方式：

启示Buff倍率 = 基准1.0 × (各枚钱币Buff倍率乘积的几何平均)
  = (Π(i=1→18) 各枚钱币的Buff倍率) ^ (1/18)

但这样全铜钱=1.0^18=1.0，全厌胜=1.1^18^(1/18)=1.1·很好！

混合配置如"五爻3金钱·其他15铜钱"：
  = (1.06³ × 1.00¹⁵) ^ (1/18)
  = 1.191016 ^ (1/18)  
  = 1.191016^0.0556
  ≈ 1.0097
  
这几乎等于没加！因为15枚铜钱稀释了3枚金币的效果。

这样设计不好——应该让钱币品质的贡献更"集中"。

更好的方案：Buff倍率由**各爻独立计算·取加权平均**：

启示Buff倍率 = Σ(爻i的Buff倍率 × 爻i的权重) / Σ(爻i的权重)

其中每个爻的Buff倍率 = 该爻3枚钱币Buff倍率的平均值，权重由变爻位置决定：
  如果该爻是变爻 → 权重 = 1.0（全额贡献）
  如果该爻不变 → 权重 = 0.3（只贡献30%·因为它不影响最终变卦启示）

这样的话：
  五爻3金钱 → 该爻Buff平均 = (1.06+1.06+1.06)/3 = 1.06
  如果五爻是变爻 → 贡献权重1.0 → Buff倍率 += 1.06 × 1.0
  
这种算法更合理——你砸钱的关键爻位如果恰好出了变爻，
它的高品质钱币就发挥了最大价值；如果没出变爻，仍然有30%贡献。
```

## 五、Buff倍率与代价减免的精确计算

### 5.1 启示Buff倍率公式

```
对于一次六爻纳币的完整结果：

Step 1：计算每个爻位的"爻位Buff倍率"
  爻位Buff倍率_i = (钱币₁倍率 × 钱币₂倍率 × 钱币₃倍率)^(1/3)

  其中每枚钱币的倍率基础值：
    铜钱=1.00  当十钱=1.02  银钱=1.04  金钱=1.06  厌胜金宝=1.10

Step 2：根据该爻是否为变爻·决定权重
  变爻权重_i = 1.0
  不变权重_i = 0.3

Step 3：计算全卦综合Buff倍率
  综合Buff倍率 = Σ(爻位Buff倍率_i × 权重_i) / Σ(权重_i)

Step 4：启示最终Buff值
  最终Buff值 = 基础Buff值 × 综合Buff倍率

Step 5：叠加上"累计特殊效果"
  累计9枚当十以上 → 如果本卦有吉位变爻(二爻/四爻/五爻)·Buff再×1.05
  累计6枚银钱以上 → 如果变爻≥2个·Buff再×1.10
  累计3枚金钱以上 → 如果本卦是凶卦(否䷋/剥䷖/困䷮等)·重roll本卦一次
  累计3枚厌胜以上 → 允许锁定1个爻位阴阳(在选币阶段预先锁定)
```

### 5.2 具体计算示例

**示例1：续航流（五爻3金钱·其他15铜钱）**

```
五爻=3金钱：
  爻位Buff倍率_五 = (1.06×1.06×1.06)^(1/3) = 1.06
  其他爻=3铜钱：
  爻位Buff倍率_其他 = (1.00×1.00×1.00)^(1/3) = 1.00

情况A：只有五爻是变爻（概率≈25.19%×其他不变概率≈75%×...）
  综合Buff = (1.06×1.0 + 1.00×0.3×5) / (1.0 + 0.3×5)
            = (1.06 + 1.50) / (1.0 + 1.5)
            = 2.56 / 2.5
            = 1.024

情况B：五爻不变+二爻变+四爻变（较好的运气）
  综合Buff = (1.00×0.3×3 + 1.06×0.3 + 1.00×1.0×2) / (0.3×4 + 1.0×2)
            = (0.9 + 0.318 + 2.0) / (1.2 + 2.0)
            = 3.218 / 3.2
            = 1.006

情况C：五爻变+二爻变+上爻变（最优运气）
  综合Buff = (1.00×0.3×3 + 1.06×1.0 + 1.00×1.0×2) / (0.3×3 + 1.0×3)
            = (0.9 + 1.06 + 2.0) / (0.9 + 3.0)
            = 3.96 / 3.9
            = 1.015
```

**关键发现：分爻配币的Buff倍率提升是克制的。** 即使五爻全金，最终启示Buff也只提升了约 1.5%-2.4%。这不是一个「砸钱就变强」的系统——是一个「砸钱稍微增加一点好运概率」的系统。微妙且平衡。

**为什么这样设计？**
- 如果砸钱=大幅提升Buff，那就变成Pay-to-Win（虽然不是真钱，但感觉一样）
- 占卜的魅力在于不确定性和"天意"——钱币只是让你多一点诚意
- 真正的强度提升来自于对变爻位置的战术选择（选对爻位投资），而不是堆金币

### 5.3 代价减免公式

```
代价减免 = 各爻位"代价减免值"的加权和

单枚钱币的代价减免值：
  铜钱=0%  当十钱=3%  银钱=5%  金钱=8%  厌胜金宝=12%

每爻的代价减免 = 该爻3枚钱币减免值的简单平均
  例如：2银+1金 = (5%+5%+8%)/3 = 6%

全卦综合代价减免 = Σ(爻i代价减免 × 权重_i) / Σ(权重_i)
  权重与Buff倍率相同：变爻=1.0·不变=0.3

代价减免上限：50%（无论花多少钱·常规代价最多减半）·**例外：** 唐开元五帝钱效果（§7.2）直接设代价归零·绕过此上限
```

**代价减免的战术意义：**

某些卦的代价非常严重。比如：
- ䷝离为火：代价是"水卦无效"→ 如果你不打算用水卦，这个代价无意义·不需要减免
- ䷄水天需：代价是"卦气恢复-20%"→ 这个代价很疼·值得减免
- ䷊地天泰：无代价 → 代价减免完全浪费

所以玩家在砸钱之前要考虑——如果摇出的卦代价不疼，钱就白花了；如果摇出代价很疼的卦，钱花得值。**这本身就是一种占卜式的决策：你不知道会摇出什么卦，但你在花钱表达"我愿意为好运付出代价"。**

### 6.2 六爻纳币 vs 锻造——玩家的两难选择

这是整个经济系统最精彩的部分——铜钱在两个核心消耗渠道之间分配：

| 消耗 | 锻造一把+9法器 | 12场BOSS全金摇卦 |
|------|:--:|:--:|
| 铜钱 | ~10,950文 | ~80,000-150,000文 |
| 星晶 | ~51 | 0（不受影响） |
| 消耗类型 | 一次性大额 | 分散多次 |
| 确定性 | 投入→必定升级（或失败） | 投入→概率提升 |
| 玩家心理 | "我的法器变强了" | "我这卦运气更好" |

**博弈论视角：**

```
一个理性的玩家面对降娄宫BOSS金无痕时：
  
  手头有 ~17,000文铜钱
  
  选择A：全铜钱摇卦（18文）+ 剩下的钱全锻造
    法器：铜钱剑Lv+5
    启示：标准概率·标准Buff
    剩余：~17,000-18-锻造≈12,982文
    
  选项B：高手流摇卦（6,606文）+ 适度锻造
    法器：铜钱剑Lv+4（因为少花了6,600文）
    启示：高概率吉位变爻·Buff×1.1-1.2
    剩余：~17,000-6,606-锻造≈6,394文
    
  选择C：全金流摇卦（18,000文·不够！需要额外攒钱）
    无法选择·钱包限制
```

**这就是设计的精妙之处：系统不需要禁止什么——钱包本身就限制了你的选择。** 前期你只能用铜钱/当十钱；中期慢慢能用银钱/金钱；终局你才用得起厌胜金宝。这个自然梯度就是最好的游戏引导。

### 6.3 连摇翻倍——终极铜钱燃烧器

```
同一次星碑访问·每次连摇的成本翻倍：

  第1次：18枚钱币（按配币方案计）
  第2次：36枚钱币（翻倍）
  第3次：72枚钱币（再翻倍）
  第4次：144枚钱币
  第5次：288枚钱币
  第n次：18×2^(n-1)枚

如果使用金钱（1,000文/枚）·追求完美启示：

  第1次：18,000文（1.8两金）
  第2次：36,000文（3.6两金）—— "差一点！再来一次！"
  第3次：72,000文（7.2两金）—— "已经花了54,000文了……再花72,000？"
  第4次：144,000文（14.4两金）—— "我疯了吗？"

四次连摇总消费：270,000文 = 27两金！！！
```

这个数字大得离谱——但这就是它的设计目的。连摇翻倍的沉没成本效应会让玩家在第二次连摇后陷入"再摇一次万一运气更好"的心理陷阱。但第三次翻倍（72,000文）就是一个清醒的耳光——"你在干什么？这些钱够你锻造两把+9法器了。"

**连摇的上限不是系统设的——是你的理智设的。**

## 七、五帝钱——不可消耗的特殊钱币

### 7.1 五帝钱在六爻纳币中的独特地位

五枚大五帝钱（秦半两/汉五铢/唐开元/宋宋元/明永乐）在收集系统中用于铜钱剑升级。在六爻纳币系统中，它们有完全不同的用途——**不可消耗·冷却制·专属特效。**

> **⚠️ 跨系统互斥说明：** 五帝钱在铜钱剑系统中的被动效果（秦半两·破甲+5%等）与在摇卦中的临时使用**不互斥**——五帝钱同时存在于铜钱剑的"镶嵌槽"和摇卦的"爻位槽"中，两者独立运作。摇卦使用五帝钱仅消耗该钱币的冷却时间（24-72h），不影响铜钱剑被动。简言之：五帝钱是"永久装备+偶尔技能"而非二选一。

```

  3. 24游戏内小时冷却（该枚钱币）

  5. 同一爻最多可放入1枚五帝钱
  6. 不同的五帝钱可放入不同的爻·互不冲突
```

## 八、连摇机制——"再摇一次"的经济学

### 8.1 连摇规则

```
连摇 = 在当前星碑·对已获得的启示不满意·追加钱币重新摇卦。

规则：
  1. 连摇必须使用相同的配币方案（18枚钱币·同品质同爻位）
  2. 第n次连摇消耗 = 18×2^(n-1)枚
  3. 每次连摇之间·玩家可以查看已摇出的启示
  4. 新启示覆盖旧启示（不可同时拥有两个启示）
  5. 每次连摇独立判定·无"保底"
  6. 离开星碑后连摇计数重置
  7. 连续在同一星碑停留超过30分钟→连摇计数也重置
```

### 8.2 连摇经济学——沉没成本的心理陷阱

```
场景：玩家在大火宫·师旷BOSS门前星碑

第1次摇卦（全银流·1,800文=1.8两银）：
  结果：䷮泽水困·减伤+25%·卦气恢复-30%
  评价：代价太重·不适合师旷的音波快攻
  
  → 选择连摇第2次（翻倍=3,600文=3.6两银）
  累计消费：1,800+3,600=5,400文=5.4两银
  结果：䷅天水讼·对太史阁+25%·野兽-15%

  但"万一有更好的呢？已经花了5.4两了..."
  
  → 选择连摇第3次（再翻倍=7,200文=7.2两银）
  累计消费：5,400+7,200=12,600文=12.6两银
  结果：䷝离为火·火卦+20%·水卦无效（师旷无弱点·一般）
  评价：不如上一个！
```

- 第4次连摇：大多数玩家在这里停止——因为数字已经大到无法忽视

## 九、定制卦象——终局的终极经济出口

### 9.1 手动画卦

解锁条件：累计3枚以上厌胜金宝（解锁爻位锁定开关·见§2.2）+ 获得至少3枚五帝钱 + 通关大火宫

> **锁定功能的两个层次：** （1）累计3枚厌胜金宝→解锁分爻配币界面中的"阴阳锁定"开关——允许在六爻纳币时锁定至多1个爻位的阴阳属性（仍为随机判定·锁定的是阳/阴而非变/不变）。这是常规六爻纳币的一部分。（2）18枚厌胜金宝+五帝钱→启动定制卦象——完全手动指定六爻阴阳和变爻·无随机判定。§9描述的是第（2）层次。
>
> 两者区别：累计3厌胜的锁定是"概率倾斜"（锁阳/阴·变爻仍随机）；定制卦象是"绝对精确"（锁阳/阴+锁变爻·一切手动）。

```
定制卦象 = 不使用甩鼠标随机摇卦·而是手动选择6个爻的阴阳和变爻状态。

条件：
  · 必须使用18枚厌胜金宝（90,000文=9两金）作为基础钱币
  · 每锁定1个爻位为指定的阴阳→需要额外投入1枚五帝钱（消耗冷却）
  · 如果该爻位同时需要指定为变爻→无需额外五帝钱（进入定制时·所有锁定爻位自动变爻）
  · 至少投入1枚五帝钱才能启动定制卦象
  
操作：
  卦盘UI展开→6个爻位每个旁边有"阳/阴"开关
  → 切换到"阳"则该爻三枚钱币强制全正面（老阳·变爻）
  → 切换到"阴"则该爻强制全反面（老阴·变爻）
  → 不切换则该爻正常随机（但使用厌胜金宝概率）
  → [确认定制] → 钱币飞出→必定按定制结果落地
  
  如果你选择全锁定→六爻全由你指定→必定是你画的卦
  这是"花钱买确定性"的极致
```

|:--:|:--:|:--:|:--:|------|
| 锁定1爻 | 90,000文 | 1枚五帝钱冷却 | 90,000文 | 保证五爻变爻·卦气-25%必出 |
| 锁定3爻 | 90,000文 | 3枚五帝钱冷却 | 90,000文 | 定制启示的战术核心（五爻+上爻+二爻） |
| 锁定6爻 | 90,000文 | 5枚五帝钱全部冷却 | 90,000文 | 九天星阵最终战·画一个完美的䷊泰卦 |

```csharp
        return true;

        AddCoins(quality, count);
        return true;
```

### 12.2 CoinDivinationAdvanced——六爻纳币核心算法

```csharp
/// <summary>
/// 六爻纳币——进阶摇卦系统核心
/// </summary>
public class CoinDivinationAdvanced {
    
    /// <summary>
    /// 单爻位配置——3枚钱币（可选+1枚五帝钱）
    /// </summary>
    [System.Serializable]
    public struct YaoSlot {
        public CoinQuality coin1;
        public CoinQuality coin2;
        public CoinQuality coin3;
        public WuDiCoin? wuDiCoin; // 可选的五帝钱·不消耗·冷却制
        
        public int TotalWenCost => 
            CoinData.GetUnitPrice(coin1) + 
            CoinData.GetUnitPrice(coin2) + 
            CoinData.GetUnitPrice(coin3);
            
        public float AverageBuffMult => 
            (CoinData.GetBuffMultiplier(coin1) + 
             CoinData.GetBuffMultiplier(coin2) + 
             CoinData.GetBuffMultiplier(coin3)) / 3f;
             
        public float AverageCostReduction =>
            (CoinData.GetCostReduction(coin1) + 
             CoinData.GetCostReduction(coin2) + 
             CoinData.GetCostReduction(coin3)) / 3f;
             
        // 三枚钱币的正面概率
        public float[] YangProbabilities => new[] {
            CoinData.GetYangBias(coin1),
            CoinData.GetYangBias(coin2),
            CoinData.GetYangBias(coin3),
        };
    }
    
    /// <summary>
    /// 执行一爻的三钱判定——返回爻类型
    /// </summary>
    public static CoinDivination.YaoType ThrowYao(YaoSlot slot) {
        // 如果放了五帝钱·秦半两=强制变爻
        if (slot.wuDiCoin == WuDiCoin.QinBanLiang) {
            // 秦半两：该爻强制变爻·老阳或老阴随机
            return Random.value < 0.5f ? 
                CoinDivination.YaoType.LaoYang : 
                CoinDivination.YaoType.LaoYin;
        }
        
        float[] probs = slot.YangProbabilities;
        int heads = 0;
        for (int i = 0; i < 3; i++) {
            if (Random.value < probs[i]) heads++;
        }
        return heads switch {
            3 => CoinDivination.YaoType.LaoYang,
            2 => CoinDivination.YaoType.ShaoYang,
            1 => CoinDivination.YaoType.ShaoYin,
            0 => CoinDivination.YaoType.LaoYin,
            _ => CoinDivination.YaoType.ShaoYang
        };
    }
    
    /// <summary>
    /// 完整六爻纳币流程
    /// </summary>
    public static AdvancedShakeResult PerformAdvancedDivination(YaoSlot[] sixSlots) {
        if (sixSlots.Length != 6) {
            Debug.LogError("六爻纳币需要6个爻位配置");
            return null;
        }
        
        var result = new AdvancedShakeResult();
        
        // 六次独立三钱判定
        for (int i = 0; i < 6; i++) {
            result.yao[i] = ThrowYao(sixSlots[i]);
            result.slotCost[i] = sixSlots[i].TotalWenCost;
        }
        
        // 计算本卦·变卦（调用父类ShakeResult.Calculate()·填充benGuaId/bianGuaId/changingYao）
        result.Calculate();
        
        // ⚠️ 重要顺序：先应用特殊效果（可能reroll·改变changingYao）·再计算Buff/Cost
        // 如果顺序反了·reroll后的Buff基于过期的changingYao数据
        
        // 应用累计特殊效果（可能触发凶卦重roll·改变yao[]和changingYao）
        ApplyAccumulatedEffects(result, sixSlots);
        
        // 应用五帝钱效果（可能改变changingYao）
        ApplyWuDiCoinEffects(result, sixSlots);
        
        // 计算综合Buff倍率（基于最终的changingYao）
        result.totalBuffMultiplier = CalculateBuffMultiplier(result, sixSlots);
        
        // 计算代价减免（基于最终的changingYao）
        result.totalCostReduction = CalculateCostReduction(result, sixSlots);
        
        return result;
    }
    
    /// <summary>
    /// 计算综合Buff倍率——各爻加权平均
    /// </summary>
    private static float CalculateBuffMultiplier(AdvancedShakeResult result, YaoSlot[] slots) {
        float weightedSum = 0f;
        float totalWeight = 0f;
        
        for (int i = 0; i < 6; i++) {
            bool isChanging = result.changingYao.Contains(i);
            float weight = isChanging ? 1.0f : 0.3f;
            float yaoBuff = slots[i].AverageBuffMult;
            
            weightedSum += yaoBuff * weight;
            totalWeight += weight;
        }
        
        float raw = totalWeight > 0 ? weightedSum / totalWeight : 1.0f;
        return Mathf.Min(raw, 1.50f); // Buff倍率上限50%（当前设计下·全厌胜+全部累计效果≈1.27·远未触顶·1.50为安全余量+未来扩展预留）
    }
    
    /// <summary>
    /// 计算综合代价减免
    /// </summary>
    private static float CalculateCostReduction(AdvancedShakeResult result, YaoSlot[] slots) {
        float weightedSum = 0f;
        float totalWeight = 0f;
        
        for (int i = 0; i < 6; i++) {
            bool isChanging = result.changingYao.Contains(i);
            float weight = isChanging ? 1.0f : 0.3f;
            float yaoReduction = slots[i].AverageCostReduction;
            
            weightedSum += yaoReduction * weight;
            totalWeight += weight;
        }
        
        float raw = totalWeight > 0 ? weightedSum / totalWeight : 0f;
        return Mathf.Min(raw, 0.50f); // 代价减免上限50%
    }
    
    /// <summary>
    /// 累计特殊效果
    /// </summary>
    private static void ApplyAccumulatedEffects(AdvancedShakeResult result, YaoSlot[] slots) {
        // 统计各品质钱币总数
        int dangShiCount = 0, yinCount = 0, jinCount = 0, yanShengCount = 0;
        foreach (var slot in slots) {
            dangShiCount += (slot.coin1==CoinQuality.DangShi?1:0)+(slot.coin2==CoinQuality.DangShi?1:0)+(slot.coin3==CoinQuality.DangShi?1:0);
            yinCount += (slot.coin1==CoinQuality.YinQian?1:0)+(slot.coin2==CoinQuality.YinQian?1:0)+(slot.coin3==CoinQuality.YinQian?1:0);
            jinCount += (slot.coin1==CoinQuality.JinQian?1:0)+(slot.coin2==CoinQuality.JinQian?1:0)+(slot.coin3==CoinQuality.JinQian?1:0);
            yanShengCount += (slot.coin1==CoinQuality.YanShengJinBao?1:0)+(slot.coin2==CoinQuality.YanShengJinBao?1:0)+(slot.coin3==CoinQuality.YanShengJinBao?1:0);
        }
        
        // 累计9枚当十以上
        if (dangShiCount + yinCount + jinCount + yanShengCount >= 9) {
            bool hasAuspicious = result.changingYao.Any(i => i == 1 || i == 3 || i == 4);
            if (hasAuspicious) result.totalBuffMultiplier *= 1.05f;
        }
        
        // 累计6枚银钱以上
        if (yinCount + jinCount + yanShengCount >= 6) {
            if (result.changingYao.Count >= 2)
                result.totalBuffMultiplier *= 1.10f;
        }
        
        // 累计3枚金钱以上→凶卦重roll（最多1次·MaxRerolls限制）
        if (jinCount + yanShengCount >= 3) {
            if (IsFierceHexagram(result.benGuaId) && !result.wasRerolled) {
                result.wasRerolled = true;
                // 重新生成全部6爻（使用相同配币方案）
                for (int i = 0; i < 6; i++) {
                    result.yao[i] = ThrowYao(slots[i]);
                }
                result.Calculate();
            }
        }
        
        // 累计3枚厌胜以上→允许锁定·但锁定在选币阶段已由玩家手动设置
        // 这里记录标记即可
        result.canLockYao = yanShengCount >= 3;
    }
    
    /// <summary>
    /// 应用五帝钱效果
    /// </summary>
    private static void ApplyWuDiCoinEffects(AdvancedShakeResult result, YaoSlot[] slots) {
        for (int i = 0; i < 6; i++) {
            if (slots[i].wuDiCoin == null) continue;
            
            switch (slots[i].wuDiCoin.Value) {
                case WuDiCoin.HanWuZhu:
                    // 汉五铢：至少2个变爻
                    if (result.changingYao.Count < 2) {
                        // 随机加一个变爻
                        var nonChanging = Enumerable.Range(0,6)
                            .Except(result.changingYao).ToList();
                        int newOne = nonChanging[Random.Range(0, nonChanging.Count)];
                        result.changingYao.Add(newOne);
                        result.RecalculateBianGua();
                    }
                    break;
                    
                case WuDiCoin.TangKaiYuan:
                    // 唐开元：代价归零
                    result.totalCostReduction = 1.0f; // 100%减免·完全消除代价
                    break;
                    
                case WuDiCoin.SongSongYuan:
                    // 宋宋元：指定上卦·此效果在选币阶段由玩家预先指定上卦的八卦类型
                    // 这里只记录·实际在六爻判定时应用（PerformAdvancedDivination中Calculate后）
                    result.forcedUpperGua = true;
                    break;
                    
                case WuDiCoin.MingYongLe:
                    // 明永乐：六爻全变概率升至5%
                    if (Random.value < 0.05f) {
                        // 强制全变
                        result.changingYao = new List<int> {0,1,2,3,4,5};
                        result.RecalculateBianGua();
                    }
                    break;
            }
        }

    public void RecalculateBianGua() {
```

```csharp
/// <summary>
/// 连摇翻倍管理器
/// </summary>
public class ChainDivinationManager {
    private int chainCount = 0;
    private YaoSlot[] currentSlots;
    private Vector3 currentStarStelePosition;
    private float lastDivinationTime;
    
    /// <summary>
    /// 获取当前连摇的消耗倍数
    /// </summary>
    public int GetMultiplier() => 1 << chainCount; // 2^chainCount
    
    /// <summary>
    /// 获取本次连摇的总钱币需求（18枚×倍数）
    /// </summary>
    public int GetRequiredCoinCount(CoinQuality quality) => 18 * GetMultiplier();
    
    /// <summary>
    /// 获取本次连摇的总文数成本
    /// </summary>
    public int GetTotalWenCost(YaoSlot[] slotTemplate) {
        int baseCost = slotTemplate.Sum(s => s.TotalWenCost);
        return baseCost * GetMultiplier();
    }
    
    /// <summary>
    /// 执行一次连摇
    /// </summary>
    public AdvancedShakeResult PerformChainDivination(YaoSlot[] slots, CoinManager coinManager) {
        // 验证是否在同一星碑·30分钟内
        if (Time.time - lastDivinationTime > 1800f) {
            chainCount = 0; // 超过30分钟·重置
        }
        
        // 检查钱币库存
        for (int i = 0; i < 6; i++) {
            int neededPerSlot = GetMultiplier();
            var slot = slots[i];
            if (coinManager.GetCount(slot.coin1) < neededPerSlot) return null; // 库存不足→连摇失败·旧启示保留不变
            if (coinManager.GetCount(slot.coin2) < neededPerSlot) return null;
            if (coinManager.GetCount(slot.coin3) < neededPerSlot) return null;
        }
        
        // 消耗钱币
        for (int i = 0; i < 6; i++) {
            int needed = GetMultiplier();
            var slot = slots[i];
            coinManager.RemoveCoins(slot.coin1, needed);
            coinManager.RemoveCoins(slot.coin2, needed);
            coinManager.RemoveCoins(slot.coin3, needed);
        }
        
        // 执行摇卦
        var result = CoinDivinationAdvanced.PerformAdvancedDivination(slots);
        
        // 更新连摇计数和计时
        chainCount++;
        lastDivinationTime = Time.time;
        
        return result;
    }
    
    /// <summary>
    /// 重置连摇状态（离开星碑或接受启示）
    /// </summary>
    public void Reset() {
        chainCount = 0;
        currentSlots = null;
    }
    
    /// <summary>
    /// 获取UI提示文本——连摇成本警告
    /// </summary>
    public string GetWarningText(YaoSlot[] slotTemplate) {
        if (chainCount == 0) return null;
        
        int nextCost = GetTotalWenCost(slotTemplate);
        string silver = $"{nextCost / 1000f:F1}两银";
        string gold = nextCost >= 10000 ? $"({nextCost / 10000f:F1}两金)" : "";
        
        return chainCount switch {
            1 => $"第2次连摇将花费 {nextCost}文（{silver}{gold}）",
            2 => $"第3次连摇将花费 {nextCost}文（{silver}{gold}）·已累计{GetCumulativeCost(slotTemplate)}文",
            3 => $"⚠️ 第4次连摇将花费 {nextCost}文（{silver}{gold}）·已累计{GetCumulativeCost(slotTemplate)}文·约等于1把法器+7→+8的锻造费用",
            _ => $"⚠️⚠️ 第{chainCount+1}次连摇将花费 {nextCost}文（{silver}{gold}）·你真的要继续吗？"
        };
    }
    
    private int GetCumulativeCost(YaoSlot[] slotTemplate) {
        int baseCost = slotTemplate.Sum(s => s.TotalWenCost);
        int cumulative = 0;
        for (int i = 0; i <= chainCount; i++) {
            cumulative += baseCost * (1 << i);
        }
        return cumulative;
    }
}
```
