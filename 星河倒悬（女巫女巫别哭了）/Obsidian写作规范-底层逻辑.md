# 星河倒悬——Obsidian 写作底层逻辑

> **定位：** 本项目所有 .md 文档的唯一写作标准。任何新增或修改文档，必须先遵守本文档。
> **与审计的关系：** `_audit.py` 中与格式相关的检查项以此文档为判断依据。

---

## 一、铁律

1. **所有 .md 文件必须有 frontmatter**（YAML 头，以 `---` 包裹）
2. **标签只用本文档定义的标准标签**，不得自创
3. **Wikilink 优先用短名**，必要时用别名
4. **命名只用中文 + 连字符**，不用空格 / 下划线 / 特殊符号
5. **每份文档必须有且仅有一个 `category`**

违反以上任意一条 → `_audit.py` 会报警。

---

## 二、Frontmatter 规范

### 2.1 必填字段

```yaml
---
category: <分类>       # 必填，从第三章的分类表选取
status: <状态>          # 必填，从第 2.2 节的状态值选取
phase: <阶段>           # 必填，从第 2.3 节的阶段值选取
tags:                   # 必填，从第四章的标签库选取
  - <标签1>
  - <标签2>
updated: YYYY-MM-DD     # 必填，最后修改日期
---
```

### 2.2 status 枚举

| 值 | 含义 | 适用场景 |
|----|------|---------|
| `🟢已完成` | 设计定稿，可直接开发 | GDD、系统设计、分析结论 |
| `🟢维护中` | 内容正确但会持续更新 | 总目录、接口定义、共享数据 |
| `🟢就绪` | 计划/路线图已确认 | 开发计划 |
| `📝编写中` | 正在撰写 | 新建文档中途 |
| `📝待补充` | 框架已有，细节不足 | 后期章节、未完成的子系统 |
| `📋参考` | 参考资料，非原创设计 | 参考游戏分析、素材库 |
| `📦归档` | 历史版本，不再使用 | 旧版设计、AI原始生成 |
| `📦废弃` | 明确废弃的文档 | 被取代的GDD |

### 2.3 phase 枚举

| 值 | 含义 |
|----|------|
| `Phase1` | 序章+星纪宫 Demo（核心原型） |
| `Phase2` | 64卦完整化+前6宫 |
| `Phase3` | 奇门遁甲+太乙神数+梅花易数 |
| `Phase4` | 12宫完整+打磨 |
| `全阶段` | 贯穿全项目的文档 |

### 2.4 可选字段

```yaml
aliases:                # Obsidian 别名，用于短名引用
  - "短名1"
  - "短名2"
cssclass:               # Obsidian CSS 类名（如需要特殊样式）
created: YYYY-MM-DD     # 创建日期（与 updated 不同时填写）
```

- 放 `装备道具/` 的文件 → `category: GDD` 或 `系统设计`

## 五、Wikilink 规范

### 5.1 引用格式

```markdown
# 同文件夹文件 → 直接用文件名
[[战斗系统GDD]]

# 跨文件夹文件 → 用相对路径（相对于项目根目录）
[[卦码系统/03-卦码实现规格书]]

# 有别名时→优先用别名
[[星河倒悬经济系统-完整设计]]    # 而非 [[16-星河倒悬经济系统-完整设计]]

# 带锚点（标题引用）
[[战斗系统GDD#三、小六爻系统]]

# 带显示文本
[[战斗系统GDD|战斗系统的完整设计]]
```

### 5.2 别名（aliases）规则

以下情况必须设置 `aliases`：

1. **文件名含数字前缀**（如 `01-EldenRing`）→ 别名 = 去掉数字前缀
2. **文件名过长**（>20字）→ 别名 = 核心关键词
3. **文件在深层子文件夹**但被频繁引用 → 别名 = 纯文件名

```yaml
# 例1：数字前缀
aliases:
  - "EldenRing黑暗之魂"

# 例2：长文件名
aliases:
  - "卦码实现规格书"

# 例3：深层文件（被引>5次时加）
aliases:
  - "经济系统完整设计"
```

### 5.3 引用检查

- `_audit.py` 会检查所有 `[[...]]` 是否指向存在的 `.md` 文件
- 不会检查外部 URL、图片引用
- 废弃文档中的断链不算错误

## 六、Callout 规范

### 6.1 可用 Callout 类型

Obsidian 原生支持以下 callout。本项目统一用法：

| Callout | 用法 |
|---------|------|
| `> [!info]` | 补充说明、背景信息 |
| `> [!warning]` | 注意事项、常见陷阱 |
| `> [!danger]` | 破坏性变更、不兼容警告 |
| `> [!tip]` | 最佳实践、推荐做法 |
| `> [!note]` | 一般备注 |
| `> [!example]` | 示例代码、示例数据 |
| `> [!quote]` | 引用参考文档 |
| `> [!abstract]` | 摘要、TL;DR |

### 6.2 折叠 Callout

长段内容使用折叠：

```markdown
> [!note]- 点击展开详细数据
> 这里放长表格或详细列表。
```

### 6.3 推荐用法

```markdown
> [!info] 与 XXX 的关系
> 此系统依赖 [[共享系统接口定义]] 中的五行枚举。

> [!warning] 注意
> BOSS 掉落值以 `_shared_data.json` 为准，此处仅为设计说明。

> [!danger] 破坏性变更
> 此版本废弃了旧货币体系（灵砂/金锭/银两），统一为铜钱+星晶。
```

## 七、文档命名规范

### 7.1 规则

- **主文件名：** 中文 + 连字符 `-`（不用空格、下划线）
- **序号：** 用中文数字（一/二/三）或阿拉伯数字 + `-`（01-）
- **特殊字符：** 只允许 `·`（间隔号），不允许 `：！？/`
- **后缀：** 全部 `.md`

### 7.2 示例

```
✅ 战斗系统GDD.md
✅ 01-EldenRing黑暗之魂经济分析.md
✅ 第一章-被剪断的丝线.md
✅ 03-卦码实现规格书.md

❌ 战斗系统 GDD.md          （空格）
❌ 战斗系统_GDD.md           （下划线）
❌ 01：EldenRing分析.md      （冒号）
❌ chapter1.md               （非中文项目统一用中文名）
```

### 7.3 文件夹命名

```
✅ 黄道十二宫/
✅ 战斗系统/、术数系统/、道宫关卡/、装备道具/、界面视觉/、决策分析/（旧分析决策/已拆分）
✅ 经济系统分析/
✅ 卦码系统/

❌ GDD/                      （太泛）
❌ 分析_决策/                （下划线）
```

| 检查项 | 规定来源 |
|--------|---------|

| TODO/待定标记 | 本文 §2.2（`📝待补充` 状态不算违规） |

> **新增检查项时：** 先更新本文档，再更新 `_audit.py`。

## 十、与 `_shared_data.json` 的关系

```
_shared_data.json  ←── 唯一数据事实源（数值、枚举、术语）
        │
        ├── 被 _audit.py 读取，用于一致性检查
        ├── 被所有 .md 文档引用（但 .md 不重复定义）
        └── 修改流程：
            1. 修改 _shared_data.json
            2. 同步更新相关 .md 文档的设计说明
            3. 运行 python _audit.py → 必须零问题
            4. 提交
```
