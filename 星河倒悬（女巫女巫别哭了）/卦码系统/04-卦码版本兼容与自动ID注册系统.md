# 卦码版本兼容与自动ID注册系统

> 核心问题：装备/法器/卦术/法印以后有增删改怎么办？卦码不能每次更新就全废。需要一套"自动适应"的ID管理体系。

---

## 一、问题的本质

当前实现规格书把所有ID映射硬编码在C#里：

```csharp
public static readonly string[] MAIN_WEAPON_NAMES = new string[4] {
    "银针", "桃木剑", "铜钱剑", "七星剑"
};
```

**如果以后：**
- 新增第5把主法器（如"玄铁尺"）→ ID=4，但bit布局只分配了2bit（0-3），存不下
- 删除了"铜钱剑"→ ID=2变成空位 → 旧卦码里的ID=2无法解码 → 旧码全废
- 改了"桃木剑"的锻造上限从+9到+12 → 旧bit布局的4bit（0-15）勉强够，但语义变了
- 新增了10种法衣 → ID 8-17 → 旧bit布局只分配了3bit（0-7）

**核心矛盾：bit是固定的，设计是变化的。**

---

## 二、解决思路：三层分离

```
┌──────────────────────────────────────────────────────┐
│ 第3层：游戏物品数据库（ScriptableObject/JSON）           │
│   → 策划在这里增删改装备。这是唯一的数据源。               │
│   → 每个物品有一个"永久GUID"和一个"当前版本ID"            │
├──────────────────────────────────────────────────────┤
│ 第2层：卦码ID注册表（自动从数据库生成）                   │
│   → 读取游戏物品数据库 → 自动分配编码ID                   │
│   → 记录每个ID的历史（哪个版本加入·是否已废弃）            │
│   → 导出为代码常量或运行时加载的配置文件                   │
├──────────────────────────────────────────────────────┤
│ 第1层：卦码编解码器（只处理"永久GUID"→"bit"的转换）        │
│   → 不依赖任何硬编码的ID映射表                           │
│   → ID=bit分配完全由注册表驱动                           │
│   → 版本兼容逻辑独立于物品逻辑                            │
└──────────────────────────────────────────────────────┘
```

**策划改了装备 → 注册表自动更新 → 编解码器自动适配。不需要程序员手动改码。**

## 三、永久GUID方案

### 3.1 核心原则

**每件物品在被创建的那一刻，获得一个永久GUID（Globally Unique IDentifier）。这个GUID永远不会变、不会被复用、不会被删除。**

```
游戏物品数据库中的每件装备：
  {
    "guid": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",  ← 永久·不可变
    "name": "桃木剑",
    "category": "main_weapon",
    "introduced_version": "1.0",
    "deprecated_version": null,    ← 如果废弃了，填废弃版本号
    "deprecated_replacement": null ← 如果有替代品，填替代品的GUID
  }
```

### 3.2 GUID的编码

GUID是128bit——太长了，不能全部塞进卦码。用两个办法压缩：

**方案A：字典压缩（推荐）**

```
注册表维护一个"GUID → 短ID"的映射表。短ID按加入顺序分配。

当编码器需要编码"桃木剑"时：
  1. 查注册表 → GUID=a1b2c3d4 → 短ID=1
  2. 检查该短ID所需的bit数（当前有4把主法器→2bit够）
  3. 编码短ID=1 → 二进制01

当解码器读到短ID=1时：
  1. 查注册表 → 短ID=1 → 主法器·桃木剑
  2. 如果玩家当前版本中短ID=1对应的物品变了 → 注册表的"deprecated"信息提供迁移
```

**方案B：分层GUID**

```
GUID压缩为"类别前缀(4bit) + 序号(8bit)" = 12bit

类别前缀：
  0=主法器  1=副手法器  2=法衣  3=头饰  4=项链
  5=手镯  6=戒指  7=法印  8=同伴  9=丹鼎
  10=上卦  11=下卦  12=天干  13=地支  14=纳音

每类最多256个序号（8bit）→ 256种主法器足够未来扩展

总计12bit → 2个六十四卦字符 → 与当前方案占用相当
```

**推荐方案A + B的混合：短ID用于bit编码，GUID用于数据库追踪。**

### 4.2 注册表的自动生成流程

```
策划操作Unity编辑器 → 添加/修改/删除装备（ScriptableObject）
  ↓ 触发OnValidate/菜单命令
代码生成器扫描所有ScriptableObject →
  1. 读取每个装备的GUID（如果没有→自动分配一个）
  2. 检查deprecated标记
  3. 计算每类装备当前数量→确定需要的encoding_bits
  4. 分配short_id（从未使用的最小ID开始·不回收废弃ID）
  5. 记录introduced_version
  6. 生成注册表JSON文件
  7. 生成C#常量文件（可选·用于编译时优化）
  ↓
编解码器启动时加载注册表 → 使用注册表中的映射进行编解码
```

### 4.3 Unity Editor工具脚本

```csharp
#if UNITY_EDITOR
using UnityEditor;
using UnityEngine;
using System.IO;

public class HexagramRegistryGenerator : EditorWindow {
    
    [MenuItem("星河倒悬/卦码系统/重新生成ID注册表")]
    public static void RegenerateRegistry() {
        var registry = new HexagramRegistry();
        
        // 扫描所有装备ScriptableObject
        string[] guids = AssetDatabase.FindAssets("t:EquipmentData");
        foreach (string guid in guids) {
            string path = AssetDatabase.GUIDToAssetPath(guid);
            EquipmentData equipment = AssetDatabase.LoadAssetAtPath<EquipmentData>(path);
            
            if (equipment.PermanentGuid == null || equipment.PermanentGuid == "") {
                equipment.PermanentGuid = System.Guid.NewGuid().ToString();
                EditorUtility.SetDirty(equipment);
            }
            
            registry.RegisterItem(
                category: equipment.Category,
                guid: equipment.PermanentGuid,
                name: equipment.ItemName,
                introducedVersion: equipment.IntroducedVersion,
                deprecatedVersion: equipment.DeprecatedVersion
            );
        }
        
        // 分配short_id
        registry.AssignShortIds();
        
        // 计算每个类别的encoding_bits
        registry.CalculateBitAllocations();
        
        // 导出为JSON
        string json = JsonUtility.ToJson(registry, prettyPrint: true);
        string outputPath = "Assets/Resources/HexagramRegistry.json";
        File.WriteAllText(outputPath, json);
        AssetDatabase.Refresh();
        
        Debug.Log($"[卦码注册表] 已重新生成·{registry.TotalItemCount}件物品·{registry.CategoryCount}个类别");
    }
}
#endif
```

## 五、编解码器的运行时适配

### 5.1 运行时加载注册表

```csharp
public class HexagramRegistry {
    public string Version;
    public int BitLayoutVersion;
    public Dictionary<string, CategoryInfo> Categories;
    
    // 正向映射：GUID → short_id
    private Dictionary<string, int> _guidToShortId = new Dictionary<string, int>();
    // 反向映射：short_id → ItemInfo
    private Dictionary<string, Dictionary<int, ItemInfo>> _shortIdToItem;
    
    public void LoadFromJson(string json) {
        // 解析JSON → 构建双向映射表
        var data = JsonUtility.FromJson<HexagramRegistry>(json);
        foreach (var cat in data.Categories) {
            _shortIdToItem[cat.Key] = new Dictionary<int, ItemInfo>();
            foreach (var item in cat.Value.Items) {
                _guidToShortId[item.Guid] = item.ShortId;
                _shortIdToItem[cat.Key][item.ShortId] = item;
            }
        }
    }
    
    // 编码时：GUID → short_id → bit
    public int GetShortId(string category, string guid) {
        if (_guidToShortId.TryGetValue(guid, out int id)) return id;
        // 如果当前版本的注册表中没有这个GUID → 这是旧码中的已废弃物品
        return -1; // 调用方处理
    }
    
    // 解码时：short_id → ItemInfo
    public ItemInfo GetItemInfo(string category, int shortId) {
        if (_shortToIdItem.TryGetValue(category, out var items)) {
            if (items.TryGetValue(shortId, out var item)) return item;
        }
        return null; // ID不存在 → 可能是新版本加入的物品·旧版不认识
    }
    
    // 检查废弃物品的替代映射
    public string GetDeprecatedReplacement(string category, int shortId) {
        var item = GetItemInfo(category, shortId);
        if (item != null && item.DeprecatedVersion != null && item.DeprecatedReplacement != null) {
            return item.DeprecatedReplacement; // 返回替代品的GUID
        }
        return null;
    }
    
    // 获取此类别的编码bit数
    public int GetEncodingBits(string category) {
        return Categories[category].EncodingBits;
    }
}
```

### 5.2 编码器适配

```csharp
// 旧编码器（硬编码）：
bits.Write(build.MainWeaponId, 2);  // ← 2bit·永远只能编码0-3·无法扩展

// 新编码器（注册表驱动）：
int bitsNeeded = _registry.GetEncodingBits("main_weapon");
int shortId = _registry.GetShortId("main_weapon", build.MainWeaponGuid);
if (shortId < 0) {
    // 这件装备在当前版本不存在 → 使用备用默认值
    shortId = 0; // 银针
}
bits.Write(shortId, bitsNeeded);
```

### 5.3 解码器适配

```csharp
// 旧解码器（硬编码）：
build.MainWeaponId = reader.Read(2);

// 新解码器（注册表驱动）：
int bitsNeeded = _registry.GetEncodingBits("main_weapon");
int shortId = reader.Read(bitsNeeded);
var itemInfo = _registry.GetItemInfo("main_weapon", shortId);

if (itemInfo == null) {
    // 这个short_id在当前版本中不存在
    // → 可能是新版本加入的物品·旧版本不认识
    // → 或者是损坏的卦码
    build.MainWeaponGuid = null;
    warnings.Add($"主法器ID={shortId}在当前版本中不存在·已跳过");
} else if (itemInfo.DeprecatedVersion != null) {
    // 这个物品已被废弃
    string replacement = _registry.GetDeprecatedReplacement("main_weapon", shortId);
    if (replacement != null) {
        build.MainWeaponGuid = replacement; // 自动映射为替代品
        warnings.Add($"'{itemInfo.Name}'已在v{itemInfo.DeprecatedVersion}废弃·已自动替换");
    } else {
        build.MainWeaponGuid = null;
        warnings.Add($"'{itemInfo.Name}'已在v{itemInfo.DeprecatedVersion}废弃·无替代品");
    }
} else {
    build.MainWeaponGuid = itemInfo.Guid; // 正常解码
}
```

## 六、版本迁移规则表

### 6.1 增/删/改 三种场景

| 场景 | 示例 | 旧码行为 | 新码行为 | 是否需要更新bit布局 |
|------|------|---------|---------|:--:|
| **新增装备** | v1.2新增"玄铁尺" | 旧版本不认识→解码时跳过/警告 | 正常编码 | ❌ 只要bit够 |
| **删除装备** | v2.0删除"铜钱剑" | 旧码中铜钱剑→自动替换或跳过 | 不再出现在新码中 | ❌ 标记deprecated即可 |
| **修改装备** | "桃木剑"锻造上限从+9→+12 | 旧码中锻造=+9以内→正常 | 新码可以锻造到+12 | ⚠️ 需要更多bit·检查预留 |
| **新增类别** | v3.0新增"副手2号槽" | 旧版本不认识→整段跳过 | 正常编码 | ✅ 需要在bit布局末尾追加 |
| **bit不够** | 主法器从4件增加到18件 | 旧版2bit→新版需要5bit | 新版正常·旧码无法被新版解码 | ✅ 需要升级主版本号 |

### 6.2 主版本号升级规则

**当bit布局发生不可兼容的变化时，主版本号+1。**

```
v1.0 → v1.1: 增删装备（bit布局不变）→ 次版本+1
v1.x → v2.0: bit布局变化（如扩充ID空间）→ 主版本+1

v2.0解码器拒绝导入v1.x的卦码（因为bit布局不同）
  → 提供"旧版迁移工具"：一键将旧码升级为新版
```

### 6.3 自动迁移工具

```csharp
public static class HexagramMigrationTool {
    
    // v1.x → v2.0 迁移
    public static string MigrateV1ToV2(string v1Code) {
        // 1. 用v1解码器解码
        var v1Decoder = new HexagramCodec("v1_registry.json");
        var build = v1Decoder.Decode(v1Code);
        
        // 2. 处理废弃物品的映射
        foreach (var item in build.GetAllItems()) {
            if (v2Registry.IsDeprecated(item.Guid)) {
                item.Guid = v2Registry.GetReplacement(item.Guid);
            }
        }
        
        // 3. 用v2编码器重新编码
        var v2Encoder = new HexagramCodec("v2_registry.json");
        return v2Encoder.Encode(build);
    }
    
    // 批量迁移整个存档的所有Build
    public static void MigrateAllBuilds(PlayerSaveData save) {
        foreach (var buildSlot in save.BuildSlots) {
            if (buildSlot.CodeVersion == "1.x") {
                buildSlot.Code = MigrateV1ToV2(buildSlot.Code);
                buildSlot.CodeVersion = "2.0";
            }
        }
    }
}
```

## 七、策划工作流——如何新增一件装备

### 7.1 策划的操作步骤

```
1. Unity编辑器中 → 右键 Create → 星河倒悬 → 装备数据
2. 填写：
   - 物品名称：玄铁尺
   - 类别：主法器
   - 首次引入版本：1.2
   - （GUID自动生成·不要手动改）
3. Ctrl+S保存
4. 菜单 → 星河倒悬 → 卦码系统 → 重新生成ID注册表
   → 自动检测到新装备 → 分配short_id=4
   → 检测到编码bits需要从2bit扩充到3bit（因为4件→5件）
   → 提示："编码bit从2→3·次版本号将升级·旧码仍兼容"
5. 确认 → 注册表更新 → 编解码器下次启动时自动加载新表
```

### 7.2 策划删除一件装备

```
1. 在装备的ScriptableObject中 → 勾选"已废弃"
2. 设置废弃版本号 → 1.2
3. 如果有替代品 → 拖入替代品的引用
4. 菜单 → 重新生成ID注册表
   → short_id=2（铜钱剑）标记为deprecated·不回收
   → 注册表记录映射："short_id=2 → 自动替换为玄铁尺(GUID=...)"
5. 所有引用铜钱剑的旧卦码 → 导入时自动替换为玄铁尺并显示警告
```

## 八、编码bit的动态分配规则

### 8.1 每类装备的初始bit分配 + 安全余量

| 类别 | v1.0数量 | v1.0分配bit | 最大容量 | 安全余量 | 预计够用到 |
|------|:--:|:--:|:--:|:--:|------|
| 主法器 | 4 | 3 | 8 | 4个空位 | v3.0 |
| 副手法器 | 8 | 4 | 16 | 8个空位 | v4.0 |
| 法衣 | 8 | 4 | 16 | 8个空位 | v4.0 |
| 头饰 | 3 | 4 | 16 | 13个空位 | v8.0 |
| 项链 | 3 | 3 | 8 | 5个空位 | v5.0 |
| 手镯 | 2 | 2 | 4 | 2个空位 | v3.0 |
| 戒指 | 2 | 2 | 4 | 2个空位 | v3.0 |
| 法印 | 12 | 4 | 16 | 4个空位 | v3.0 |
| 同伴 | 12 | 4 | 16 | 4个空位 | v3.0 |
| 丹鼎 | 6 | 3 | 8 | 2个空位 | v3.0 |
| 上卦 | 8 | 3 | 8 | 0个空位 | **永远8个** |
| 下卦 | 4 | 2 | 4 | 0个空位 | **永远4个** |
| 天干 | 10 | 4 | 16 | 6个空位 | **永远10个** |
| 地支 | 12 | 4 | 16 | 4个空位 | **永远12个** |
| 纳音 | 30 | 5 | 32 | 2个空位 | **永远30个** |

**安全规则：永远预留至少2倍于当前数量的bit空间。** 当某类装备数量增长到接近最大容量的一半时，在下一次主版本升级时扩大bit分配。

### 8.2 自动检测何时需要扩容

```csharp
public static class BitCapacityMonitor {
    // 每次生成注册表时自动调用
    public static List<string> CheckCapacity(HexagramRegistry registry) {
        var warnings = new List<string>();
        
        foreach (var cat in registry.Categories) {
            int currentCount = cat.Value.Items.Count(i => i.DeprecatedVersion == null);
            int maxCapacity = 1 << cat.Value.EncodingBits;
            float usage = (float)currentCount / maxCapacity;
            
            if (usage > 0.75f) {
                warnings.Add($"⚠ {cat.Key}: {currentCount}/{maxCapacity} ({usage:P0}) —— 建议在下次主版本升级时扩充bit");
            }
            if (usage > 0.90f) {
                warnings.Add($"🚨 {cat.Key}: {currentCount}/{maxCapacity} ({usage:P0}) —— 紧急！bit已接近极限·不能再新增装备");
            }
        }
        
        return warnings;
    }
}
```
