# Obsidian 格式标准 —— 设计文档底层规范

> **适用范围：** 本项目所有 .md 设计文档
> **强制等级：** BLOCKING —— 违反此规范的文档视为不合格
> **权威源：** `星河倒悬（女巫女巫别哭了）/Obsidian写作规范-底层逻辑.md`（执行细节）
> **本文件定位：** 项目级规范摘要，供所有 agent 快速查阅

---

## 一、铁律（5条·不可违反）

1. **所有 .md 文件必须有 frontmatter**（YAML 头，以 `---` 包裹）
2. **标签只用标签库定义的标准标签**，不得自创
3. **Wikilink 优先用短名**，跨文件夹用相对路径
4. **命名只用中文 + 连字符**，不用空格 / 下划线 / 特殊符号
5. **修改后运行 `python _audit.py`**，必须零问题才能提交

---

## 二、Frontmatter 规范

### 2.1 必填字段

```yaml
---
category: <分类>
status: <状态>
phase: <阶段>
tags:
  - <标签1>
  - <标签2>
updated: YYYY-MM-DD
---
```

### 2.2 status 枚举

| 值 | 含义 | 适用场景 |
|----|------|---------|
| `🟢已完成` | 设计定稿，可直接开发 | GDD、系统设计、分析结论 |
| `🟢维护中` | 内容正确但会持续更新 | 总目录、接口定义、共享数据 |
| `🟢就绪` | 计划/路线图已确认 | 开发计划 |
| `📝编写中` | 正在撰写 | 新建文档中途 |
| `📝待补充` | 框架已有，细节不足 | 后期章节、未完成的子系统 |
| `📋参考` | 参考资料，非原创设计 | 参考游戏分析、素材库 |
| `📦归档` | 历史版本，不再使用 | 旧版设计、AI原始生成 |
| `📦废弃` | 明确废弃的文档 | 被取代的GDD |

### 2.3 phase 枚举

| 值 | 含义 |
|----|------|
| `Phase1` | 序章+星纪宫 Demo |
| `Phase2` | 64卦完整化+前6宫 |
| `Phase3` | 奇门遁甲+太乙神数+梅花易数 |
| `Phase4` | 12宫完整+打磨 |
| `全阶段` | 贯穿全项目 |

## 四、Wikilink 规范

### 4.1 引用格式

```markdown
同文件夹：  [[战斗系统GDD]]
跨文件夹：  [[卦码系统/03-卦码实现规格书]]
带别名：    [[16-星河倒悬经济系统-完整设计|经济系统完整设计]]
```

### 4.2 必须添加关联文档段落的文档类型

以下类型的文档必须在文末添加 `> **关联文档：**` 段落：

- 所有 GDD 文档
- 系统设计文档
- 接口/规范文档
- 开发计划文档

## 五、数据权威规则

### 5.1 单一事实源（Single Source of Truth）

```
数值修改工作流：
  ① 修改 _shared_data.json（权威数据源）
  ② 同步更新相关 .md 文档中的引用
  ③ 运行 python _audit.py
  ④ 零问题 → 可以提交
```

### 5.2 _shared_data.json 管理的数据

- 枚举定义（WuXing、CoinQuality、CurrencyType）
- BOSS 掉落（铜钱、星晶、材料）
- 物价系数（12道宫 ×1.0~×2.5）
- 锻造成本（单次成功 + 期望成本）
- 钱币面值与概率
- 废弃模块/货币清单

## 六、审计门禁

### 6.1 自动审计（`_audit.py`）

每次修改设计文档后**必须**运行，检查项：
- 废弃货币是否在活跃GDD中残留
- WuXing枚举是否在非权威文档中重定义
- 物价系数是否与 `_shared_data.json` 一致
- BOSS掉落是否与 `_shared_data.json` 一致
- Wikilink是否有断链
- TODO/待定标记是否遗留
- C#代码块花括号是否平衡

### 6.2 Obsidian 健康扫描（`_obsidian_scan.py`）

定期运行，检查项：
- 文档是否有 frontmatter
- Wikilink 是否全部可解析
- 标签是否全部合法
- 文档被引用频次

---

## 七、新文档创建检查清单

创建新设计文档时，逐项确认：

- [ ] 文件名：中文 + 连字符，无空格/下划线
- [ ] Frontmatter：5个必填字段全部填写
- [ ] category：从标签库选取
- [ ] status：选择合适的 emoji 状态
- [ ] tags：至少2个，从标签库选取
- [ ] Wikilink：引用了所有关联文档
- [ ] 关联段落：文末有 `> **关联文档：**`
- [ ] `_audit.py` 通过
- [ ] 如涉及数值→已在 `_shared_data.json` 中定义
